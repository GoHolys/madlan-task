# Implementation plan

## Goal

Ship one public Hebrew RTL CSM-facing evidence assistant that can answer a focused set of useful questions from the supplied deals CSV without letting the LLM invent calculations or silently broaden unsupported requests.

## Architecture

```text
Browser
  ↓ POST /api/ask
OpenAI Responses API
  ↓ strict QueryPlan
semantic validation + explicit-question drift checks
  ↓
parameterized DuckDB query
  ↓
result + n + exclusions + sources + evidence
  ↓
deterministic Hebrew presentation
```

## Code boundaries

- `src/contracts.ts` — shared closed contracts.
- `src/normalization.ts` — raw CSV parsing/normalization rules.
- `src/data.ts` — canonical snapshot, duplicate policy, quality metadata.
- `src/database.ts` — in-memory DuckDB lifecycle and ingestion only.
- `src/analytics.ts` — deterministic whitelisted analytics/evidence.
- `src/planner.ts` — natural-language planning and provider configuration only.
- `src/guardrails.ts` — deterministic checks for explicit city/metric/rooms/year drift.
- `src/presentation.ts` — deterministic Hebrew result copy and warnings.
- `src/service.ts` — plan validation, orchestration, and failure mapping.
- `src/ui/*` — display and interaction only.
- `app/api/*` — thin HTTP boundaries.

No business calculations in React. No SQL generated by the LLM. No ORM or second backend.

## Definition of done

- Hebrew/RTL UI is usable on desktop and mobile.
- Representative aggregate, comparison, list and quality questions work.
- Every numeric answer exposes sample size and evidence.
- Unsupported conditions fail closed.
- Month-only dates are not given invented day precision.
- Duplicate/conflicting IDs have an explicit policy.
- Model timeout/failure returns no fallback number.
- CSM guide includes a customer reply.
- AI log records one caught bad AI/tooling assumption.
- Typecheck, lint, tests and production build pass.
- Railway config and health endpoint are ready for public deployment.
